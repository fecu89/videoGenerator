# Video Generator

動画専用コード・検証・テストは `runs/<run>/scripts/`、素材は `assets/`、中間生成物は `.render-cache/` に保存します。`render-source.json` に依存ファイルを宣言し、通常の制作では共有コードの変更や Git コミットを不要にします。新しい設定 v7 の Blender EEVEE Shadow Pool は既定で 2048 MB、既存 run の設定は維持します。

[Run render sources](video_harness/docs/run-render-sources.md)

[English](README.md) · [한국어](README.ko.md) · **日本語** · [简体中文](README.zh-CN.md) · [Español](README.es.md)

テーマをひとつ渡すと、AIエージェントが調査し、台本を書き、声を付け、3Dの画面まで作って解説動画を1本仕上げます。このフォルダはそのための作業フォルダです。

人がすることは**選ぶ、読む、直したい点を書く、承認する**だけです。コードを書いたりコマンドを覚えたりする必要はありません。重要な段階ごとにWeb画面が開くので、そこでボタンを押すか意見を書き込みます。

> **言語について。** このハーネスは韓国語を基本にしています。メインのナレーションは韓国語で、Web画面とエージェント向けの指示ファイルも韓国語で書かれています。以下のボタン名は画面の表示どおりに記し、日本語訳を添えています。

## 何を作ってくれるのか

- 1〜3分の韓国語の解説動画(横長・縦長・正方形から選択)
- 韓国語のナレーションとBGM
- 英語・日本語・中国語・スペイン語の音声と字幕(必要な言語だけ選択)

画面は生成AIによる動画ではなく、Blenderで計算して描く3Dシーンです。そのため、天体の位置や力の向きのように正確さが必要な内容が、シーンごとにぶれません。

## 必要なもの

| 必要なもの | 理由 |
|---|---|
| Apple silicon搭載のMac(M1以降) | 音声を作るモデルがこの環境でしか動きません |
| AIコーディングエージェント(Claude Code、Codexなど) | 調査、台本、画面設計を担当します |
| Python 3.13 | ハーネス本体 |
| FFmpeg | 映像と音声を結合します |
| Blender 5.2 | 3D画面を描きます。`/Applications/Blender.app` にインストールします |
| espeak-ng | スペイン語の音声を作るときだけ必要です |

## インストール

ターミナルでこのフォルダに移動し、以下を一度だけ実行します。よく分からなければ、エージェントに「READMEのとおりにインストールして」と頼んでもかまいません。

```bash
python3 -m pip install -r requirements.txt
brew install ffmpeg espeak-ng
```

Blenderは [blender.org](https://www.blender.org/download/) からダウンロードし、アプリケーションフォルダに入れます。

初めて音声を作るときに、音声モデルが自動でダウンロードされます。インターネットが必要なのはこのときだけで、数分かかります。それ以降は、インターネットもAPIキーも使わず、このコンピュータの中だけで動きます。

## 始め方

このフォルダをエージェントで開き、次のように伝えます。

> 動画生成ハーネスに従って動画を作って。テーマは「土星に環がある理由」。

台本の下書きがあれば一緒に貼り付けます。PDFを渡して、その内容で作ってほしいと頼むこともできます。使いたい3Dモデルがあれば `assets/` フォルダに入れて、エージェントに知らせてください。

エージェントはこのフォルダの [AGENTS.md](AGENTS.md) に書かれた順序に従います。人が関わるのは、以下の6つの段階だけです。

## 全体の流れ

| 段階 | エージェントがすること | 人がすること |
|---|---|---|
| 1. 設定 | 設定画面を開きます | テンポ・声・音楽・出力を選び、**저장 후 닫기**(保存して閉じる) |
| 2. 台本 | 調査して台本の下書きを書き、Webに表示します | 読んで意見を書くか、**대본 승인**(台本を承認) |
| 3. 音声 | 承認された台本で音声を作ります | 待ちます |
| 4. プレビュー | 画面を設計し、代表的なシーンを描いてWebに表示します | 見て意見を書くか、**프리뷰 승인**(プレビューを承認) |
| 5. 初稿 | 低い画質で動画全体を作ります | 再生して確認し、チャットで `초본승인`(初稿承認)と返信 |
| 6. 完成版 | 本来の画質で作り直します | 待ちます |

承認は3回です。台本、プレビュー、初稿。前の段階を承認するまで、次の段階は始まりません。時間のかかる作業を、誤った台本や画面のまま走らせないための仕組みです。

### 段階1 — 設定を選ぶ

![設定画面](readme/settings.png)

左の一覧にある4つのグループだけ見れば十分です。

- **영상 템포**(動画のテンポ): 落ち着いた解説 / 通常の動画 / ショート向けテンポ。話す速さと画面が切り替わる間隔が一緒に決まります。
- **목소리**(声): 全体の話し方を選びます。**목소리 미리 듣기**(声の試聴)を開くと、保存する前に聞けます。
- **배경음악**(BGM): `bgmusic/` フォルダの音楽から選び、音量を決めます。空にすると音楽なしで作ります。
- **출력**(出力): 動画の規格、追加の言語、字幕を動画に焼き込むか別ファイルで受け取るかを決めます。

選び終えたら、右下の **저장 후 닫기**(保存して閉じる)を押します。ウィンドウが閉じると、エージェントが次の段階に進みます。前回の設定がそのまま残っているので、変えるものがなければすぐに閉じてかまいません。

**고급 옵션**(詳細オプション)は折りたたまれています。普段は開く必要がありません。項目ごとの説明は [settings.md](settings.md) にあります。

### 段階2 — 台本の確認

![台本確認画面](readme/story.png)

- **左の一覧**でシーンを選ぶと、中央にそのシーンの台本と画面に映す内容が表示されます。
- **이 장면의 수정 사항**(このシーンの修正点)に直したい点を書きます。「この文は前のシーンと重なっている」「もっとやさしく説明して」のように、普段の言葉で書けば十分です。
- **영상 아이디어**(映像のアイデア)は任意です。希望する画面や演出があれば書き、なければ空欄のままにします。
- 動画全体への意見は、いちばん下の **영상 전체에 대한 수정 의견**(動画全体への修正意見)を開いて書きます。

書き終えたら、右上のボタンを押します。

- **수정 의견 저장**(修正意見を保存): 直したい箇所があるとき。保存したら、エージェントに「修正意見を書いたよ」と伝えてください。Web画面からエージェントに自動で通知されることはありません。
- **대본 승인**(台本を承認): このままでよいとき。承認すると画面が閉じ、音声の制作が始まります。

保存しただけで承認を押さなければ、次の段階には進みません。エージェントが台本を直したら、同じ画面を再読み込みして、もう一度読んでから承認します。

### 段階3 — 音声を作る

エージェントが自動で進めます。シーン20個ほどで数分かかります。

まれに、音声モデルが特定の文をゆっくり読みすぎて検査を通らないことがあります。その場合、エージェントが読点を外したり文を少し直したりすることを提案します。台本が変わることになるので、もう一度承認を求めます。

### 段階4 — プレビューの確認

![プレビュー確認画面](readme/preview.png)

動画全体を描く前に、シーンごとに代表的な画面を数枚、先に見せます。ここで直すのがいちばん速く済みます。

- **大きな画像の下にある小さな画像**を押すと、そのシーンの中を時間の順に見られます。**이미지 크게 보기**(画像を拡大)で拡大します。
- **나레이션 대본**(ナレーション台本)の下の再生ボタンで、そのシーンの音声を聞けます。
- **영상대본**(映像台本)は、その時間に画面で何が起きるかを文章で書いたものです。
- **이 장면의 수정 사항**(このシーンの修正点)に、画面についての意見を書きます。「矢印が長すぎる」「衛星が必要ないシーンにも映っている」のように、見たままを書けば十分です。

右上のボタンは3つです。

- **수정 의견 저장**(修正意見を保存): 意見だけを保存します。
- **수정 반영 후 프리뷰 다시 만들기**(修正を反映してプレビューを作り直す): 意見を保存し、作り直しを依頼します。押すと画面が閉じます。エージェントがすぐに続けない場合は「プレビューに意見を出したよ」と伝えてください。
- **프리뷰 승인**(プレビューを承認): このままでよいとき。承認すると画面が閉じます。意見が書かれている間は押せません。

エージェントが直すと、新しいプレビューで確認画面がもう一度開きます。納得がいくまで繰り返します。

プレビューの画像は小さく(長辺384ピクセル)描きます。手早く確認するためのものなので、細部がつぶれて見えることがあります。

### 段階5 — 初稿の確認

プレビューを承認すると、エージェントが低い画質で動画全体を作り、`final-draft.mp4` ファイルの場所を知らせます。音声と音楽が入っています。自分で再生して、動きが不自然なところや発音がおかしいところを確認してください。エージェントは動画を再生したり音を聞いたりすることができません。

- 直したいところがあれば、チャットで伝えます。画面だけを直す場合、音声は作り直しません。
- 問題なければ、チャットで `초본승인`(初稿承認)と返信します。

### 段階6 — 完成版

本来の画質で描き直します。進行状況を表示するWeb画面のアドレスをエージェントが知らせ、終わるとその画面に動画が表示されます。

かなり時間がかかります。土星の動画(2分38秒、1920×1080)では、初稿に約17分、完成版に約2時間15分かかりました。コンピュータをつけたまま、ほかのことをしていてかまいません。

## 成果物の場所

動画ひとつごとに `runs/日付-テーマ/` フォルダができます。

| ファイル | 内容 |
|---|---|
| `final.mp4` | 完成動画(韓国語音声、BGM) |
| `final-<lang>.mp4` | 韓国語・英語・日本語・中国語・スペイン語の音声と音楽を含む動画。字幕は選択でき、個別音声トラックは過去の実行用です |
| `subtitles/` | 言語別の字幕ファイル(`.srt`、`.ass`) |
| `video-only.mp4` | 音声なしの動画 |
| `final-draft.mp4` | 段階5で確認した初稿 |
| `story-review.md` | 台本と出典 |
| `research.md` | 調査内容と、画面で誇張または省略した部分 |

`runs/` フォルダはgitにコミットされません。必要な動画は別の場所に移しておいてください。

## 知っておくとよいこと

- **意見は具体的なほど効果的です。** 「なんか変」よりも「9番のシーンの矢印が衛星の中心に合っていない」のほうが一度で直ります。シーン番号を添えるとさらに確実です。
- **「進めて」は承認ではありません。** 承認として扱われるのは、Webの承認ボタンか、チャットでのはっきりした承認(「대본 승인」「프리뷰 승인」「초본승인」)だけです。
- **台本を直すと音声を作り直します。** 画面だけを直す場合、音声はそのまま使います。そのため、台本は段階2で十分に仕上げておくのがおすすめです。
- **初めて扱うテーマは時間がかかります。** 画面を描くコードを、エージェントがテーマに合わせて新しく書く必要があるためです。すでに作ったテーマに近ければ、ずっと速く済みます。
- **外部の3Dモデルと音楽には条件があります。** `assets/` に入れたモデルの出典とライセンスは `assets/CREDITS.md` に記録します。動画を公開するときに作者の表記が必要なモデルがほとんどで、非営利限定のものや改変禁止のものもあります。
- **翻訳はエージェントが書きます。** ネイティブによる確認はありません。各シーンの長さに合わせるため、韓国語より短く縮めた文が含まれることがあります。

## さらに詳しく(開発者向け)

エージェントが内部で使うコマンドです。自分で実行することはほとんどありません。

```bash
python -m video_harness settings-ui                 # 設定画面
python -m video_harness story-ui runs/<run>         # 台本確認画面
python -m video_harness voice runs/<run>/script.json
python -m video_harness preview runs/<run>          # 計画の検査 → 代表シーンのレンダリング → プレビュー画面
python -m video_harness preview-ui runs/<run>       # プレビュー画面だけを開き直す
python -m video_harness produce runs/<run> --quality draft
python -m video_harness produce runs/<run> --quality final
python -m video_harness validate runs/<run>
```

最終動画が検査を通ると、同じコマンドが続けて言語別の縦型ショート（`shorts/shorts-<lang>.mp4`、台本でショートに残すと決めたシーンのみ、最長3分）と `upload.md` を作ります。`upload.md` は言語別のタイトル・説明と、3Dモデル・BGM・音声の出典表記で、完成画面にコピーボタン付きで表示されます。

以下の文書は韓国語で書かれています。

- 作業全体の順序と承認ルール: [video_harness/agent/WORKFLOW.md](video_harness/agent/WORKFLOW.md)
- 台本と画面の基本的な演出基準: [video_harness/agent/DIRECTION.md](video_harness/agent/DIRECTION.md)
- ハーネスの構造: [video_harness/docs/architecture.md](video_harness/docs/architecture.md)
- Blenderのシーンを追加する方法: [video_harness/docs/blender-rendering.md](video_harness/docs/blender-rendering.md)
- 問いの連鎖と画面の連続性の検査: [video_harness/docs/creative-gates.md](video_harness/docs/creative-gates.md)
- シーン転換の原則: [video_harness/docs/continuous-transitions.md](video_harness/docs/continuous-transitions.md)
- 声の演技と間: [video_harness/docs/voice-acting.md](video_harness/docs/voice-acting.md)

テストは、APIキーやモデルのダウンロードなしで実行できます。

```bash
python -m pytest -q -p no:cacheprovider
```

Three.jsレンダラーを使う場合や、Web画面のブラウザテストを実行する場合にのみ、以下の追加インストールが必要です。Blenderだけで作るなら不要です。

```bash
cd video_harness/science_renderer
npm ci
npx playwright install chromium --only-shell
```
