# 대상을 이어가는 영상 전환

설명 영상은 앞 장면의 대상을 따라 다음 구조와 관계로 이동하는 흐름을 먼저
설계한다. 나레이션 씬 번호는 음성과 검토 구간을 나누는 기준이며 화면 교체
명령이 아니다. 연결할 근거가 있는 인접 장면은 같은 객체와 시간축을 사용한다.

## 전환을 고르는 기준

| 설명 관계 | 기본 연출 | 유지할 대상 |
| --- | --- | --- |
| 전체 → 내부·부분 | 전체를 확대하고 층을 열거나 관심 부분을 따라 내부 구조를 드러낸다. | 전체 모형과 선택한 부분의 위치 관계 |
| 기본 단위 → 집합 구조 | 한 단위에서 물러나며 주변 단위들이 모여 연결되게 한다. | 처음 보인 단위의 객체와 연결 위치 |
| 구조 → 다른 구조의 재료 | 다음 구조에 필요한 구성 요소를 남기거나 분리하고 주변 요소들이 붙게 한다. | 남긴 구성 요소의 정체성·개수·결합 관계 |
| 기존 대상 → 새 설명 대상 | 기존 대상이 후퇴하거나 옆으로 빠지는 동안 새 대상이 들어온다. | 퇴장·진입 방향과 두 대상의 공간 관계 |
| 구성 요소 → 종류·서열 | 해당 부분을 따라 종류를 펼쳐 보이고, 요소들이 이동해 배열을 만든다. | 출발 요소와 각 종류·배열의 대응 |

확대나 설명 대상의 변경만으로 `cut`을 선택하지 않는다. 부분과 전체의 관계,
구성 요소의 재사용, 비교 대상의 퇴장·진입으로 이어갈 수 있는지 먼저 검토한다.
서로 다른 장소·시간 등 연결이 설명을 흐리는 경우에는 구체적 이유를 기록하고
컷을 사용한다. 모든 주제에 하나의 긴 카메라 비행을 강제하지 않는다.

설명 대상을 이어 보여 주는 이동과 실제 물리·화학적 변화를 구별한다. 광물에서
탄소로 관심을 옮기는 연출은 규소가 탄소로 변하는 반응이 아니다. 염기 하나에서
네 종류를 펼쳐 보이는 연출은 염기가 네 개로 분열하는 반응이 아니다. 설명용
변형과 생략은 실행 폴더의 `research.md`에 남긴다.

## 계획 계약

공통 계획의 `primary_event`와 로컬 계획의 기존 검토 문자열
`review_visual_description`, `review_framing`, `review_camera_movement`에
다음 내용을 쓴다. `labels` 외의 새 스키마 필드를 추가하지 않는다.

1. 앞 장면에서 계속 추적할 대상과 실제 객체 ID.
2. 전환 시작·끝 프레임, 시작·종료 위치와 크기, 확대·후퇴·집결·분리 경로.
3. 다음 대상이 어디에서 나타나고, 앞 대상이 언제 화면 밖으로 나가는지.
4. 라벨은 `labels`로 선언하며 이전 비트 라벨이 사라진 뒤 다음 라벨이 나타난다.
   전환 중 대상이 차지할 영역.

전환 구간은 나레이션 경계의 앞뒤에 걸쳐 설계할 수 있다. 각 beat의 기존
반개구간과 오디오 시작점은 유지하고, 경계를 넘는 동작을 공통 시간으로 평가한다.
연결된 비트는 가능한 한 하나의 `visual_sequence`와 장면 그래프로 묶는다.
시퀀스를 나눠야 한다면 같은 객체 ID·좌표계·공통 시간과 경계 상태를 이어받는다.

`continuity-plan.json`의 모든 인접 경계를 검토한다. 실제 3D 동작으로 이어지는
경계는 `continuous_3d`로 선언하고, `actors`에는 실제로 이어서 추적할 모형의
객체 이름을 연결한다. 장면과 무관한 정지 객체를 대신 등록하지 않는다.
`reason`에는 위 설명 관계와 선택한 전환을 구체적으로 쓴다.

## 렌더러 구현

- 필요한 모형은 장면 그래프에 구성해 두고 같은 객체를 재사용한다. 씬 번호가
  바뀔 때 전체 모형을 숨기고 다음 모형을 재생성하는 방식으로 연결하지 않는다.
- 위치·회전·크기·재질·카메라를 공통 canonical frame 또는 시뮬레이션 시간의
  함수로 계산한다. 같은 프레임을 다시 요청하거나 순서를 바꿔 요청해도 같은
  상태를 얻어야 한다. 이전 `sample()` 호출 결과에 이동량을 계속 더하지 않는다.
- 변환은 부모까지 반영한 세계 좌표로 확인한다. 카메라 이동과 모형의 배율
  변경 중 실제 사용하는 방식을 계획에 정확히 기록한다.
- 확대할 때 표면이 내부 모형과 설명 글자를 가리지 않도록 층을 열거나 표면을
  화면 밖으로 이동시킨다. 퇴장·가림이 끝나기 전에 객체를 갑자기 숨기지 않는다.
- 큰 규모 차이를 빠르게 확대해 넘길 때는 도착한 내부 구조를 알아볼 시간을
  둔 다음 구성 단위를 분리한다. 예를 들어 흑운모 → 판상 원자 배열 → 그 배열의
  사면체 하나 순서를 유지하며, 전체 배열을 건너뛰고 사면체만 출현시키지 않는다.
- 다음 구조로 가져갈 구성 요소의 개수와 결합을 먼저 정한다. 예를 들어
  탄소 사슬에서 글리신 구성으로 옮길 때는 두 탄소와 그 결합을 유지하고,
  나머지 탄소가 퇴장한 뒤 N/O/H를 조립한다.
- 분리되는 요소의 결합선은 먼저 해제하거나 끝점에 맞춰 갱신한다. 이동하는
  원자 사이에 긴 선이 남지 않게 한다. 연결 유지가 필요한 사슬은 접힐 때도
  결합 위치와 길이를 보존한다.
- 글자는 별도 여백에서 읽을 수 있는 크기를 유지한다. 필요하면 글자만
  페이드하며, 두 장면 전체를 디졸브하거나 정지 프레임을 늘여 연속 동작을
  대신하지 않는다. 기존 FFmpeg 전환 효과는 별도의 편집 선택이다.
- 설명에 필요 없는 제작용 XYZ 축은 화면에서 제거한다. 계산·검증용 좌표계는
  유지하며, 정보를 전달하는 그래프 축·단위·방향 표기는 남긴다.
- Blender의 편집 가능한 `.blend`에 변환·곡선·재질 애니메이션을 저장하고,
  실제 렌더 상태는 기존 continuity 캡처 경로로 기록한다.

## 검토와 전달

전체 렌더 전에 각 설명의 대표 프레임과 전환의 시작·중간·끝을 직접 본다.
특히 큰 대상이 지나가는 구간, 구성 요소가 떨어지는 순간, 여러 요소가 모이는
구간의 겹침·잘림·긴 결합선을 확인한다. 검토 파일과 시점을 `visual-review.md`에
기록한다.

```bash
python -m video_harness check-creative plan runs/<run>
python -m video_harness produce runs/<run> --quality draft
python -m video_harness check-creative render runs/<run> --quality draft
```

계획 검토와 현재 영상 생성대본 승인은 기존 제작 절차를 따른다. 위 명령은
승인을 대신하지 않는다. 저해상도 초본의 QA가 통과하면 `final-draft.mp4`를
먼저 보여준다. 고해상도 제작 지시가 있으면 `--quality final`로 진행한다.

자동 검사는 선언한 객체와 카메라의 경계 상태, 방향, 시간 등을 확인한다.
검사 통과만으로 화면 전체의 연속성이나 과학적 의미가 보증되지는 않는다.
실제 MP4에서 추출한 전환 프레임과 움직임을 함께 검토한다.

## 전환 구간의 정지 화면 검사

장면 연결부의 같은 프레임만으로 의도된 전환을 실패 처리하지 않는다.
첫 비트에 선언된 `entry_transition`은 지원하는 효과와 유효한 길이
(`0 < duration_seconds <= 1`)를 확인하고, 실제 출력 FPS에 맞춰 전환 종료
시점과 그 뒤 0.1초의 프레임을 비교한다. 광학적 깊이 렌더러의 선언된 밝기
매치 전환도 같은 방식으로 0.3초의 밝기 복귀 이후를 확인한다.

전환 뒤 화면이 이전 프레임에서 벗어나고 다시 움직여야 통과한다. 선언이
없거나 잘못된 전환, 전환 후에도 지속되는 정지, 프레임 누락·시간 불일치는
계속 실패 처리한다. 검사 결과 파일을 직접 통과로 바꾸지 않는다.

구현한 예:

  `BondingFlowGallery`, `build()`에서 객체 구성, `sample(frame)`에서 공통 시간 평가,
  `bake()`에서 편집용 키프레임 저장.
- [작업 입력 검증](../blender_renderer/bonding_math.py): 해당 그래프의 10개 장면
  순서와 빈틈없는 시간축 검사. 이 장면 수와 화학 모형은 이 예제 전용이며
  다른 주제의 공통 제약이 아니다.
