# 생성 음성의 쉼 검증

`두 번째 준위`를 `두 번째, 준위`처럼 읽는 문제는 전사문이 정확해도 생긴다.
`voice_pause_qa.py`는 **합성할 때 이미 알고 있는 구절 경계와 실제 파형**을
대조한다. 별도 인식 모델을 로드하지 않는다. 단어 강제 정렬이나 의미 판별을
구현했다고 보고하지 않는다.

## 자동 실행과 호환성

새로 `typed` 음성을 생성하는 실행은 `voice-pause-policy.json`을 만들고 검사한다.
이 파일은 **현재 effective settings에서 읽은 음성·QA 설정의 검사 스냅샷**이다.
별도의 고정 쉼 기준이나 사용자 설정을 덮어쓰는 옵션이 아니다. 실행의
`run-settings.json`을 우선하며 설정 파일 자체는 갱신하지 않는다. 기존 실행은
이 파일이 없으면 예전 제작 경로를 유지한다.
기존 실행에서 `check-voice`를 명시적으로 실행하면 검사 대상에 편입된다.
편입된 실행은 통과 기록이 없거나 오래되었으면 계획·프리뷰·제작을 차단한다.
게이트나 정책 파일을 삭제하여 실패를 우회하지 않는다.

```bash
# 실제 MP3만 재검사. 대본·음성·영상은 수정하거나 재생성하지 않는다.
python -m video_harness check-voice runs/<run>
python -m video_harness check-voice runs/<run> --language ja
```

기록은 `voice-pause-gate.json`, 추가 언어는 `voice-pause-gate-<lang>.json`이다.
종료 코드 0은 통과, 1은 검사 실패, 2는 명령/정책 오류다. 실패 보고서에는
장면 번호, 문장 번호·원문, MP3 내 초 단위 시점과 감지한 쉼 길이를 남긴다.
문장 안의 **정확히 어느 단어 사이인지**는 자동 추정하지 않는다.

## 무엇을 검사하는가

1. Qwen 원본 후보에서 구절 안의 의도하지 않은 쉼을 검사한다. 기존의 내부
   무음 자르기 **전에** 실행한다. 실패하면 기존 후보 재시도 예산 안에서 다른
   시드를 쓰고, 모두 실패하면 합성을 중단한다. 화자·톤·대본은 바꾸지 않는다.
2. Kokoro도 자르기 전에 검사한다. 같은 입력의 결정적 합성을 반복하지 않고
   실패를 보고한다. 해당 언어의 구절/대본 검토 뒤 필요한 장면만 다시 만든다.
3. 인코딩된 실제 MP3를 FFmpeg로 디코딩해 다시 검사한다. 쉼표·의미 구분·강조·
   문장 경계는 `pause_events`, `output_seconds`, 실제 문장 여백으로 찾는다.
   선언된 쉼의 누락·길이/위치 불일치도 실패한다. 쉼 위치 근처를 통째로
   검사에서 제외하지 않으므로 그 경계에 긴 쉼이 붙어도 잡는다.
4. MP3·생성 보고서·대본의 해시와 검사 정책·알고리즘 버전을 기록한다.
   재합성, 대본·타이밍·정책 변경 뒤에는 이전 통과 기록을 재사용하지 않는다.

의도한 쉼은 승인 전 `sentence_pauses`나 문장부호로 명시한다. 나머지 합성
구절 전체가 붙여 읽기 검사 대상이다. `두 번째 준위` 같은 묶음 내부에는
쉼표나 semantic/emphasis 경계를 지정하지 않는다. 단어마다 별도 합성하여
보호 구간을 만든다고 해결하지 않는다. 승인된 대본/쉼 메타데이터를 바꿔야
하면 기존 대본 승인 절차를 따른다.

## 판정 기준과 한계

10ms 창의 RMS로 무음을 찾는다. 사인파의 영점이나 짧은 자음 폐쇄를 긴 쉼으로
세지 않는다. 기준은 창 RMS의 95백분위보다 35dB 낮은 수준(절대 하한 1e-5)이다.
미지정 쉼의 상한은 **현재 실행의 `voice.max_internal_pause_ms`**다. 원본 후보는
이 값과 직접 비교하고, 최종 MP3는 **구절마다 실제 적용된 `tempo_factor`로 나눈
상한**과 비교한다. RMS 창 경계의 양자화 오차로 10ms를 허용한다. `speaking_rate`,
목표 음절 속도, `max_tempo_factor`에 따라 실제 합성기가 선택한 배율을 쓰며,
느린 구절에 같은 문장의 가장 빠른 배율을 잘못 적용하지 않는다.

의도한 쉼은 `pause_mode`에 따라 `comma_pause_ms`, `semantic_pause_ms`,
`emphasis_pause_ms`, `sentence_pause_ms` 또는 legacy의 문장 앞뒤 여백과
대조한다. 이 여백은 배속하지 않는다. 위치·길이 허용 오차는
`qa.duration_tolerance_seconds`, 전체 디코딩 길이 오차는 여기에
`qa.audio_packet_tolerance_seconds`를 더한 값이다. 문장 바깥의 무음은 내부
쉼으로 판정하지 않지만 선언된 문장 여백은 별도로 대조한다.

예를 들어 설정이 내부 쉼 120ms를 허용하면 원본의 110ms 쉼을 고정 100ms
규칙으로 실패시키지 않는다. 반대로 원본 상한이 120ms이고 실제 배율이 1.5면
최종 파일의 내부 쉼 기준은 80ms(+창 오차)다. 의도한 600ms 문장 쉼을
80ms로 줄이거나 실패시키지 않는다. 설정이 바뀌면 과거 게이트는 오래된
것으로 판정하며, 명시적 재검사/재합성에서 검사 스냅샷을 다시 만든다.

검사 스냅샷의 숫자를 직접 고쳐 설정을 우회하지 않는다. 설정 변경은 기존
설정 흐름을 따른다. 언어·화자에 따라 정상적인 호흡/무성음도 실패할 수
있으므로 실패 시 원문과 파형을 먼저 검토한다.
음성에 존재하는 숨소리·유성 늘임·억양만의 끊김, 오독·누락·화자 변화는 이
검사만으로 검증하지 못한다. ASR 일치나 게이트 통과를 직접 청취로 기록하지 않는다.

이전 보고서에 문장별 실제 `output_seconds`가 없으면 `timing_unavailable`로
실패한다. 쉼으로 나눈 문장의 구절별 배율/시간(`phrase_spans`)이 없으면
`phrase_timing_unavailable`로 기록한다. 문장 전체의 최대 배율을 모든 구절에
대입하거나 추정 시간·균등 분할로 통과시키지 않는다. 기존 `legacy` 음성은
자연 쉼표 위치의 타이밍이 없을 수 있어 오탐이 가능하다. 기존 설정을 자동
갱신하거나 승인 없이 음성을 다시 만들지 않는다.

## 실패 처리와 검토 기록

- 후보 검사와 최종 MP3 검사에 실패하면 새 음성을 정식 산출물로 반영하지 않는다.
  한국어의 대본·MP3·생성/길이 보고서·성공 게이트는 같은 게시 트랜잭션에 포함된다.
  실패/중단은 기존 MP3를 보존하며 게이트는 미통과로 남는다.
- `unexpected_pause`: 해당 문장과 시점의 파형을 확인하고 같은 승인 대본으로
  해당 장면만 재생성한다. 그래도 실패하면 대본/쉼 위치 수정안을 검토한다.
- `planned_pause_mismatch`: 메타데이터의 실제 출력 시점과 MP3를 대조한다.
  후처리로 일부를 잘랐다면 문장·쉼 타이밍도 검증해야 하며 과거 보고서를
  그대로 인증 근거로 쓰지 않는다.
- `pause_check_unavailable` 또는 오래된 해시: 파일·대본·생성 보고서를 복구한 뒤
  재검사한다. 검사 불가는 통과가 아니다.
- `release-review.md`에 게이트 파일/알고리즘/정책, 음성 해시, 문제 문장·시점,
  검사 방법과 재생성 결과, 남은 청취 항목을 남긴다. 이 게이트는 쇼츠에서
  새로 생긴 접합부의 발화·자막 싱크 검사를 대신하지 않는다.
