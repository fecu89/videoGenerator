# 기본 연출 기준

분광형 영상과 흑체복사 영상에서 사용자가 반복해서 요청하고, 최종 수정본에서
확인한 원칙이다. 새 영상의 대본·화면 설계·검토에 공통으로 적용한다. 현재
작업의 명시적인 사용자 지시가 이 기본값보다 우선한다.

## 1. 답이 다음 질문을 만드는 대본

- `문제 → 해결 → 그 답으로 생긴 새 문제 → 해결`의 인과 사슬을 만든다.
  관련 사실이나 법칙을 차례로 나열하는 구성으로 끝내지 않는다.
- 각 장면에서 무엇을 해결했으며, 왜 다음 장면이 필요한지 설명할 수 있어야 한다.
  자료에 없는 문제나 반전을 만들어 사슬을 강제하지 않는다.
- 사용자가 대본을 저장했다고 하면 파일을 다시 읽고 최신 저장본을 기준으로 삼는다.
  제작에 사용한 대본 사본과 출처를 실행 폴더에 보존한다.
- 화면만 수정하는 요청에서는 확정된 나레이션·음성·장면 길이를 재사용한다.
  필요한 변경 범위를 넘어 대본이나 음성을 함께 다시 만들지 않는다.

## 2. 밝고 자연스러운 첫 목소리

- 첫 문장은 호기심을 만드는 내용으로 시작하고, 말투는 저장된 음성 설정을 따른다.
  어둡고 장중한 도입을 기본으로 쓰지 않는다. 문장의 기능을 감정 연기 지시와
  혼동하지 않는다.
- 숫자와 단위는 자연스러운 한국어로 읽는다. 예를 들어 10,000 K는
  `만 켈빈`이며 `십천 켈빈`이 아니다. 전문용어도 음성 검토 대상에 포함한다.
- 발음용 표현은 대본 단계에서 정리한다. 확정된 원문을 TTS 단계에서 몰래
  치환하지 않는다. 문장별 전달 지시와 기존 음성 길이 계약을 함께 지킨다.
- **목소리 일관성을 우선한다.** 한 문장 안과 장면 사이에서 같은 화자의
  음색·말투·체감 음량이 유지되는지 확인한다. 밝은 시작도 다른 화자처럼
  들리는 과한 톤 변화로 구현하지 않는다.
- 문장별 연기는 현재 음성 설정을 따른다. `voice.emotion_mode=off`이면
  `sentence_delivery`를 생략하거나 빈 배열로 두고, 대본·대화·검토본에 감정과
  강도를 표시하지 않는다. `script_only`일 때만 모든 문장에 연기 지시를 작성한다.
  밝은 전체 말투를 선택했더라도 문장별 연기를 자동으로 추가하지 않는다.
- Qwen은 같은 Sohee 화자와 선택된 톤 프리셋을 유지한다. 문장별 연기를
  선택한 경우에만 도입·질문·해답의 연기를 더한다. 설정·누락 차단·청취 검토는
  [대본 연기](../docs/voice-acting.md)를 따른다.
- 설정·지시문 해시가 같고 자동 전사가 일치해도 음색 일관성이 검증된 것은
  아니다. 대표 문장과 이어 붙인 음성의 문장 내부·경계 강약을 검토한다.
  급격한 음색 변화가 남으면 재생성하고 음성 검토 전에는 전체 렌더로
  진행하지 않는다. 음량 보정만으로 화자가 바뀌는 문제를 해결했다고 보고하지 않는다.

- Qwen 속도는 목표 음절 속도와 최소 말하기 배율로 검토한다. 기본 최소 배율
  1.0에서는 이미 빠른 음성을 감속하지 않는다. 가속은 `voice.max_tempo_factor`
  이내로 제한하며, 실제 발음·문장 여백과 장면 길이를 함께 확인한다.

## 3. 객체가 주인공, 글자는 자막으로

- 영상의 설명은 대상의 움직임·변형·강조와 나레이션이 맡고, 글은 **자막**이
  전담한다. 기본 정책(`text_policy: subtitles`)에서는 화면 안 글자가 **없다**.
  제목·부제목·라벨·지시선·수식·단위·축 이름을 장면 객체로 넣지 않는다. 자막은
  영상 위에 합성되는 별도 층이며 장면 안의 객체가 아니다.
- 수식·단위처럼 글로 써야 하는 정보는 나레이션 문장 안에서 말로 풀고, 자막이
  그 문장을 그대로 담는다.
- 자막은 한국어 마스터의 문장별 음성 타이밍에서 만들어지고 언어별
  (`ko/en/ja/zh/es`) 완성본 `final-<lang>.mp4`에 번인된다. 하단 중앙, 아래 5%·
  좌우 6% 안전 여백, 글자 높이 화면의 4.4%, 최대 2줄, 흰 글자·어두운 외곽선,
  배경판 없음. 언어별 한 줄 한도(ko 22, ja/zh 20, en/es 42)를 넘는 문장은 두
  큐로 나뉜다. 규격은 `video_harness/subtitles.py`가 고정한다.
- `subtitles` 실행에서 계획에 `labels`가 있으면 `text-plan-gate`가, 렌더에 보이는
  글자 객체(FONT)나 콜아웃이 있으면 `text-render-gate`가 실패한다.
- **예외: 수식.** 사용자가 꼭 필요하다고 지정한 수식(2026-09-24 와도 영상의
  `ζ+f=const`)은 `kind: formula` 라벨로만 둔다. 모든 언어 완성본이 같은 화면을
  쓰므로 기호만 쓰고(`일정` 대신 `const`), 작은 크기(`size: small`, 약 105px)로
  대상 옆 가장자리에 둔다. 비트당 2개까지이며 선언한 수식 콜아웃과 그 글자
  객체만 허용되고, 잘림·겹침·지시선 검사를 받는다. 설명하는 도형에 붙으므로 대상 가림은 실제 프레임으로 검토한다.

### 핵심 단어 라벨 (`text_policy: keywords` 전용)

`keywords` 정책을 명시한 실행에서만 아래 규칙으로 화면 글자를 허용한다.
`subtitles` 실행에는 적용하지 않는다.

- 영상의 설명은 대상의 움직임·변형·강조가 맡는다. 글자는 나레이션이 가리키는
  대상을 짚어 주는 **핵심 단어**만 남긴다. 문장형 부제목, 나열 구절, 화살표로
  이어 붙인 요약은 쓰지 않는다. 그 내용은 객체의 동작과 지시선으로 보여 준다.
- 화면 글자는 로컬 계획의 비트별 `controller_options.labels`로만 선언한다.
  `text`(한글 8자 이하, 공백 1개 이하), `anchor`(장면 객체 이름), `side`
  (`top/bottom/left/right`), `emphasis`(`none/glow/scale`, 기본 `glow`),
  `kind`(`word/formula/unit`). 비트당 `word`+`formula`는 **2개**까지, `unit`은
  개수에서 빼되 4개 이하. 산문 검토 문자열 안에 따옴표로 문구를 숨기지 않는다.
- 설명이 필요한 부분은 그 객체를 먼저 강조(`glow`·`scale`)하고, 객체 표면에서
  꺾인 지시선을 글자까지 잇는다. 지시선과 글자는 같은 색이다. 렌더러는 공용
  `CalloutLayer`(Blender `callout.py`, Three.js `callout.ts`)로만 글자를 그린다.
- 글자는 anchor 바깥 `side` 여백에 두고 화면 가장자리 4% 안전 영역 안에 넣는다.
  글자 뒤 배경판·반투명 띠·상단 배너, 하단의 작은 보조 문구는 쓰지 않는다.
  `공간 배치 축약` 같은 제작 보조 문구는 검토 문서에 기록한다.
- 축 이름·단위처럼 과학적 의미가 있는 표기는 `kind: unit`으로 남긴다. 수식은
  `kind: formula`로 길이 제한 없이 두되 개수 제한은 지킨다.

### 기본 화면 크기

2026-09-22 와도 확대 구도의 주요 대상 점유율을 유지한다. 글자는 등급이 하나다.

| 항목 | 고정 참조값과 적용 방법 |
| --- | --- |
| 기준 화면 | 1920×1080, 16:9. 다른 출력 해상도에서는 같은 비율로 환산한다. |
| 주요 대상 | 둥근 단일 대상은 화면 높이 약 2/3, 전체 구조를 보여주는 대상은 약 90%. 참조: 지구 지름 약 720px, 관람차 최대 길이 약 960px. |
| 단어·수식 라벨 | 1080p에서 글자 높이 약 210px(`size=1.56`). `CalloutLayer`가 `hud_scale = 화면 너비 / 16`으로 확대·후퇴 중에도 유지한다. |
| 단위 라벨 | 그 절반(약 105px). |
| 지시선 | 객체 표면 → 꺾임 → 글자 가까운 변 중앙의 3점 선. 굵기도 `hud_scale`에 비례한다. |
| 페이드 | 비트 시작·끝에서 0.4초. 전환 중에는 이전 비트 라벨이 먼저 사라지고 다음 라벨이 뒤에 나타난다. |

여러 대상을 비교할 때는 실제 크기 비율을 유지하고 라벨은 각 대상에 하나씩
지시선으로 붙인다. 겹침·잘림은 `side`와 카메라·구도로 고치며 전체를 축소해
빈 화면으로 돌아가지 않는다. `review_framing`에는 대상의 점유율과 카메라만
적고, 글자는 `labels`에 적는다.

[콜아웃 기하](../blender_renderer/callout_math.py)(`keywords` 전용).

## 4. 모든 장면에서 설명하는 움직임

- 첫 장면만 움직이는 영상으로 만들지 않는다. 장면마다 곡선 생성, 최고점
  이동, 표면 확대, 광선 진행, 흡수선 변화 등 설명에 필요한 변화를 설계한다.
  계산 결과를 읽는 홀드는 의도를 명시하고, 정지 이미지를 영상처럼 취급하지 않는다.
- 공간 구조와 통과 과정을 보여줄 때 실제 3D를 우선한다. 별에는 구면과
  표면 질감을 사용한다. 물리 과정이 바뀌는 부분은 카메라 이동만으로 대신하지 않는다.
- 광선·화살표·연결선은 역할이 명확한 최소 수만 쓴다. 하나의 빛이 이동하는
  과정이면 그 빛 하나를 추적한다. 여러 별을 비교할 때는 필요한 경로만 각각 둔다.
- 원인과 결과가 이어져야 한다. 예를 들어 별빛이 프리즘을 통과해 **스펙트럼**으로
  펼쳐지는 과정, 대기를 빠져나오며 흡수선이 생기는 과정을 시간 순서로 보여준다.
- 요청된 가속·후퇴는 속도 변화와 주변 물체의 시차로 체감되게 만든다.
  모든 장면에 빠른 이동이나 장식적인 카메라 회전을 강제하지 않는다.

## 4-1. 영상 속도

유효 `run-settings.json`의 영상 템포와 해석된 세부 값을 따른다. 새 프로젝트는
쇼츠 템포이며, 차분한 설명·일반 영상을 선택했으면 쇼츠 기준을 덮어씌우지 않는다.

- 구도(timeline beat)는 `local_video.target_beat_min_seconds`–`target_beat_max_seconds`를
  목표로 한다(차분 5–8초, 일반 3–5초, 쇼츠 2–4초). 둘 다 0인 과거 실행은 기존 계획을 따른다.
  나레이션 장면 길이와 구도 길이를 혼동하지 않는다. 긴 문장 안에서도 구도·강조를 나눈다.
- 구도 사이에는 `local_video.camera_transition_seconds` 동안 카메라를 연속 이동한다.
  렌더 작업의 같은 키를 읽어 이동 시간을 정하고, 개별 카메라 경로의 실제 반영을 확인한다.
  값이 없는 과거 렌더 작업은 기존 동작을 유지한다. 컷은 장소·시간이 바뀌는 곳에 쓴다.
- 문장 앞·뒤 여백과 `local_video.scene_gap_seconds`가 정하는 호흡에 화면을 맞춘다.
  쉼에서도 객체와 물리 시간이 이어져야 한다. 완성 영상의 전역 배속으로 맞추지 않는다.
- `plan-video`가 검토본에 표시하는 구도 길이 범위 밖 항목을 검토한다. 감속 전파·그림자 진입처럼
  연속 관찰이 필요한 물리 과정은 더 길게 유지할 수 있으며 해당 비트의
  `controller_options.pacing_exception_reason`에 이유를 기록해 검토본에 표시한다.
  속도 때문에 원인→결과의 중간 단계를 생략하지 않는다.

## 5. 장면 전환과 도구 선택

- [대상을 이어가는 전환](../docs/continuous-transitions.md)을 기본으로 설계한다.
  전체를 확대해 내부를 드러내고, 한 단위에서 물러나 주변 단위의 집결을
  보여주며, 구성 요소 하나를 다음 구조까지 유지한다. 기존 대상의 퇴장과
  다음 대상의 진입도 같은 공간에서 이어간다.
- 같은 대상을 이어 보는 장면은 위치·자전·카메라 상태를 이어 간다. 예를 들어
  회전하는 별의 글자만 먼저 사라지고 그 상태에서 카메라가 멀어지게 한다.
  나레이션 경계에서 객체를 재생성하거나 시간을 초기화하지 않는다. 전환은
  경계 앞뒤에 걸칠 수 있으며, 추적할 객체와 시작·종료 상태를 계획에 쓴다.
- 공간 관계를 설명하는 연속 장면은 동일한 3D 배치에서 카메라의 회전·이동·확대로
  다음 설명을 드러낸다. 앞 장면의 마지막 상태와 다음 장면의 첫 상태를 공유하고,
  별도 렌더 파일 사이에서도 카메라·천체 위치·시간이 이어지는지 검사한다.
- 설명 대상이나 규모가 바뀌어도 부분·전체, 분리·집결 관계로 이어갈 수 있는지
  먼저 확인한다. 서로 다른 관측 장소·시간 등 연속 이동이 설명을 흐리는
  경우에는 구체적 이유를 남기고 컷으로 전환한다. 이어질 수 없는 장면을 긴 비행이나 임의의 천체 이동으로
  억지로 잇지 않는다. 전환 중간 프레임에서도 대상 잘림과 글자 겹침을 확인한다.
- 독립된 발표 화면 사이에는 명료한 컷을 기본으로 쓴다. 디졸브로 이전 별과
  다음 수식이 겹치지 않게 한다. 같은 공간 안의 전환은 객체와 카메라의 연속
  움직임을 먼저 검토한다. 동적인 영상이라는 이유로 전환 효과를 남발하지 않는다.
- 라벨은 전환 중에도 `hud_scale`로 같은 화면 크기를 유지하며, 이전 비트 라벨이 먼저 사라진 뒤 다음 라벨이 나타난다.
  설명에 필요 없는 제작용 XYZ 축은 제거하되 과학적 의미가 있는 축·단위는 남긴다.
  설명 초점의 이동을 실제 물리·화학적 변환처럼 보이게 만들지 않는다.
- Blender는 입체 대상·재질·카메라, Three.js는 정밀 도표·표식, Python은
  계산·음성·합본·검증에 활용할 수 있다. 장면에 맞게 조합하되 모든 도구를
  한 영상에 억지로 넣지 않는다. 실제 사용한 렌더러와 편집 원본을 기록한다.
- 관측값·가상 예제·정성적 비교를 구별한다. 비율을 수치로 제시하면 기하와
  계산도 그 비율을 지킨다. 작은 비교 대상을 확대하면 확대 표시를 가까이 둔다.

## 6. 미리보기와 완성본 검토

새 배치는 전체 렌더 전에 대표 장면과 변화 전·중·후 프레임으로 확인한다.
렌더러에서 투영 경계를 얻을 수 있으면 글자 잘림과 대상·글자 겹침도 검사한다.
크기와 배치는 프레임을 직접 보며 확인하고, 이동·페이드·전환 중의 겹침까지 살핀다.

[시각 검토 양식](templates/visual-review.md)을 실행 폴더의 `visual-review.md`로
복사해 결과와 실제 프레임·시점·검사 보고서 경로를 남긴다. 이 양식은 에이전트의
시각·내용 검토 기록이며, CLI의 미디어·스키마 검사와 함께 사용한다. 실행하지
않은 검사를 통과로 표시하거나 자동 전사를 직접 청취한 것으로 기록하지 않는다.

완성 MP4의 재생, 해상도·FPS·길이, 음성 경계, 검은 화면과 의도하지 않은
정지를 확인한다. 시각 수정만 한 경우 음성 재사용 여부도 확인한다. 검토용
장면별 영상과 완성본을 함께 제공하고 이전 완성본은 보존한다.

## 7. 식현상의 관측 방향

- 기본 관측자는 북반구로 둔다. 일식·월식의 관측 원반은 천구 북쪽이 위,
  동쪽이 왼쪽인 화면 기준을 사용하고 제작 문서에 좌표 기준을 기록한다.
- 일식에서는 태양에 대한 달의 서→동 운동을 **화면 오른쪽→왼쪽**으로
  보여준다. 하루 동안 태양·달이 하늘을 가로지르는 일주 운동과 구별한다.
- 월식을 달 중심에 고정해 보여줄 때는 달 표면을 덮는 지구 그림자의
  상대 이동과 달 자체의 공전 방향을 구별한다. 사용자가 승인한 방향을 유지한다.
- 우주에서 본 정렬·지구 표면 그림자와 지상 관측 원반은 카메라 기준이
  다르다. 단순히 전체 화면을 좌우 반전해 모든 방향을 바꾸지 않는다.
- 북쪽에서 내려다보는 공간 모식도에서 달은 지구 주위를 반시계방향으로
  돈다. 같은 달에 접근하는 카메라를 쓸 때는 그림자가 덮이는 쪽도 실제
  진입 방향과 맞추고, 지상 관측 원반의 좌우 기준과 혼동하지 않는다.
- 방향 수정 뒤에는 시작·중간·끝 프레임에서 태양의 어느 쪽부터 가려지는지
  확인하고, 다른 관측 장면과 글자 배치가 유지되는지 검사한다.

기준 자료: [미국천문학회 관측 방향 설명](https://eclipse.aas.org/node/672),
[NASA 식현상 FAQ](https://science.nasa.gov/eclipses/faq/).

## 연속성은 최종 출력에서 확인한다

[필수 검사](../docs/creative-gates.md)에 장면별 질문·해답·다음 질문의 근거와
모든 인접 전환의 종류·이유를 남긴다. 같은 천체와 카메라를 사용하는 연속
장면은 앞뒤 실제 렌더 상태로 검사한다. 자연스러운 컷은 이유를 명시한다.
월식 등 관측 방향이 중요한 장면은 세계 좌표와 화면 좌표를 구분한다.
회전 전·중·후, 그림자 진입 위치와 빛의 굴절 방향을 각각 검토한다.
프리즘의 분산, 대기의 산란, 빛의 굴절을 구별한다. 월식의 붉은 달 설명에서는
프리즘처럼 무지개 색띠를 펼치지 않는다. 짧은 파장 성분이 여러 방향으로
산란하면서 투과광이 붉어지는 과정을 보여주고, 남은 빛의 경로가 대기 안에서
지구 쪽으로 휘는 굴절을 별도로 구별한다. 대기 밖에서는 다시 직진한다.
세계 좌표의 방향·연속성 검사만 통과했다고 과학적 원리까지 검증된 것으로
보고하지 않는다. 실제 화면이 대본의 물리 과정과 일치하는지 의미를 검토한다.
