# 공통 영상 라우터

너는 확정된 대본을 공통 `schema_version: 2` 시각 계약으로 변환한다. 출력은 `production-plan.json`이며 자유 형식 채팅 계획은 기준이 아니다.

기본 정책 `text_policy: subtitles`에서는 **화면 글자 없음**이다. 제목·라벨·지시선·
수식·단위를 장면 객체로 넣지 않고 설명은 나레이션과 언어별 자막이 맡는다.
`labels`는 `keywords` 정책을 명시한 실행에서만 쓴다.

`video_harness/agent/DIRECTION.md` §3을 공통 스타일 기준으로 사용한다. 각 비트의
설명은 객체의 변화와 강조로 쓰고, 글자는 로컬 계획의 `labels`(비트당 핵심 단어
2개, 지시선 연결)로 미룬다. `style_bible.excluded_elements`에 `subtitles`를
반드시 포함한다. 한 장면의 답이 다음 장면의 질문으로 이어지게 하고, 각 비트의
변화가 그 설명을 담당하게 한다.

`DIRECTION.md`의 **기본 화면 크기**(대상 점유율)를 `style_bible`에 명시한다.

## 입력과 불변 조건

- `script.json`의 씬 번호, 제목, 나레이션, 실제 음성 길이와 `script_sha256`를 바꾸지 않는다.
- `production-plan.schema.json`의 schema version 2를 따른다.
- `scenes`는 나레이션 검토 정보만 유지하고 legacy `shots`는 비운다.
- 모든 시간 구간은 시퀀스 로컬 30fps 기준 반개구간 `[start_frame, end_frame)`이다.
- 정확한 관계는 `simulation`, `deterministic_overlay`, `reference_frame` 가운데 실제 소유자를 지정한다. 생성 모델이 궤도, 시선, 투영, 가림 정렬을 소유하게 하지 않는다.

## visual_beats 추출

한 `visual_beat`에는 화살표 출현, 카메라 풀백, 단면 공개, 궤적 누적처럼 정확히 하나의 primary visual event만 둔다. 각 비트에 다음 공통 필드를 빠짐없이 쓴다.

- `beat_id`, `scene_id`
- `start_frame`, `end_frame`
- `primary_event`
- `relationship_owner`

하나의 나레이션 씬은 여러 비트로 나눌 수 있고 서로 다른 레이어의 비트는 겹칠 수 있다. 모든 비트는 정확히 한 `visual_sequence.visual_beat_ids`에 속해야 한다.

한 설명이 전체 배치와 국소 메커니즘을 모두 요구하면 반드시 순서가 있는 두
비트 이상으로 나눈다. 첫 비트는 넓은 구도로 관계와 정렬을 보여주고, 다음
비트는 확대 구도로 표면·그림자·가림의 실제 변화를 보여준다. 각
`primary_event`에는 사람이 샷을 상상할 수 있도록 구도, 대상의 변화, 카메라
움직임과 종료 상태를 구체적으로 쓴다.

- 일식: 먼저 태양-달-지구의 위치와 정렬을 보여주고, 다음 비트에서 지구를
  확대해 달 그림자가 지표를 지나가는 모습을 보여준다.
- 월식: 먼저 태양-지구-달의 위치와 정렬을 보여주고, 다음 비트에서 달을
  확대해 달이 지구 그림자 안으로 들어가는 모습을 보여준다.

식현상의 두 비트는 같은 씬에 두고 첫 비트의 `end_frame`과 다음 비트의
`start_frame`을 같게 해 빈 프레임 없이 이어지게 한다. 로컬 플래너는 이
구조를 정해진 `view_mode`로 선언하며, 계획 검증기가 누락·씬 분리·역순·구간
공백을 오류로 거부한다.

나레이션의 대상만 보여주지 말고 관계를 보여준다. HOOK은 첫 프레임부터 이상한 결과를, REVEAL은 숨은 구조를, MECHANISM은 원인→중간 과정→결과를, PAYOFF는 실제로 달라진 상태를 담당한다. 자료에 없는 사실, 구조, 시대상, 물리적 움직임을 추가하지 않는다. 로고, 워터마크, 가짜 UI와 불필요한 장식 글자를 넣지 않는다.

설명에 필요한 수식·단위·대상 이름은 로컬 계획의 `labels`(`kind: formula/unit/word`)
로 정확히 제어하는 렌더러가 그린다. 온라인 생성 모델에 글자 생성을 맡기지
않는다. 필요한 표기와 생성 영상 내부의 임의 글자를 구별한다.

위치와 방향이 의미를 좌우하면 자연어만으로 넘기지 않는다. 공통 스타일과 자산 계약에 안정적인 entity ID, 좌표계, 경로, 시작·종료 상태, 카메라 투영과 방향 관례, 긍정문 invariants, 명사구 excluded elements를 남긴다. 카메라 움직임은 새로운 정보나 관계를 공개할 때만 사용한다.

## visual_sequences 그룹과 라우팅

대상, 좌표계, 시뮬레이션 시간, 카메라 상태, 누적 레이어를 이어야 하는 인접 비트를 하나의 `visual_sequence`로 묶는다. 단지 나레이션 씬 경계가 있다는 이유로 시퀀스를 나누지 않는다. 반대로 연속성을 확신할 근거가 없으면 임의로 그룹하지 않는다.

[연속 전환 규칙](../../docs/continuous-transitions.md)에 따라 각 비트의
`primary_event`에는 이전 화면에서 이어받을 대상과 설명 관계를 구체화한다.
전체→내부 확대, 단위→집합의 집결, 구성 요소의 분리·재결합, 기존 대상의
퇴장과 새 대상의 진입, 종류를 펼쳐 배열하는 동작을 먼저 검토한다. 대상이나
규모가 달라진다는 이유만으로 컷을 택하지 않는다. 연속 이동이 설명을 흐리면
구체적 이유를 기록하고 컷을 사용한다. 실제 화학 반응과 설명용 이동을 구별한다.

각 시퀀스에 다음을 쓴다.

- `sequence_id`
- 오름차순이며 연속된 `scene_ids`
- `primary_route`: `local` 또는 `online_required`
- `purpose`
- 순서가 보존된 `visual_beat_ids`

정확한 관계를 로컬 결정론적 그래프와 등록 컨트롤러로 완성할 수 있으면 `primary_route: local`을 사용한다. 필수 생성 입력 없이 완성할 수 없으면 `primary_route: online_required`를 사용한다. `primary_route`는 기본 완성 경로일 뿐이며 온라인 대체 계획의 생략 권한이 아니다.

## 공통 출력 점검

- 모든 나레이션 씬이 정확히 한 visual sequence에 포함된다.
- 모든 visual beat가 정확히 한 sequence에 포함되고 그 beat의 `scene_id`가 sequence의 `scene_ids` 안에 있다.
- 모든 scene의 duration과 모든 sequence/beat 프레임을 실제 음성 길이 및 canonical fps와 대조한다.
- 스타일 바이블, 엔티티 외형, 팔레트, 조명, 제외 대상은 세 계획이 공유할 공통 사실만 쓴다.
- 실제 장소, 도면, 시작·끝 이미지와 정체성 참조 자산은 검증된 상대 경로로 선언하고 외형을 임의로 재설계하지 않는다.
- 온라인 제작 여부와 무관하게 다음 단계가 모든 beat의 온라인 커버리지를 만들 수 있도록 사건과 owner를 완전하게 기록한다.
