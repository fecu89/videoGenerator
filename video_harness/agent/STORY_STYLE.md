# 대본의 흐름과 말투

2026-10-19 진근점 이각 대본에서 사용자가 직접 쓴 도입을 되살린 뒤,
사용자가 “지금 이 흐름이랑 어투가 너무 마음에 든다”고 확인한 기준이다.
새 대본 작성과 원고 편집에 적용한다. 현재 사용자의 다른 요청이 있으면 그 요청을 우선한다.

## 기준이 된 도입

> 여기 태양 주위를 도는 행성이 있습니다. 태양을 한 초점으로 하는 타원 궤도를 돌고 있죠. 그런데 문제가 있습니다.
>
> 관측 자료와 케플러의 법칙을 이용하면 공전 궤도, 근일점 같은 것들은 구할 수 있습니다. 근일점으로부터의 각도까지도요.
>
> 하지만 어느 지점에서 태양과 행성 사이의 거리 자체를 구하는 건 쉽지 않습니다. 직접 재기도 어려워 환장할 노릇이죠.
>
> 이에 생각을 바꿉니다. 타원 궤도의 장반경, 이심률, 진근점 이각이라는 것으로 거리를 구하기로 말이죠.

이 예문은 말투와 전개의 참조다. 다른 주제에서도 행성·천문학자·같은 대사를
가져다 쓰는 고정 템플릿이 아니다. 이 선호 확인은 개별 영상의 대본·프리뷰·초본 승인을 대신하지 않는다.

## 흐름: 상황에서 막히는 지점으로

1. **구체적인 대상을 먼저 보여준다.** “여기 …이 있습니다”처럼 지금 화면에서
   볼 수 있는 대상과 상태를 담담하게 놓는다. 인사나 주제 안내부터 하지 않는다.
2. **이미 알 수 있는 것을 짚는다.** 시청자가 어느 정도 이해했다고 느끼게 한다.
   “각도까지도요”는 막연한 강조가 아니라, 뒤에 남을 거리 문제와 비교할 전제다.
3. **그런데도 남는 문제를 꺼낸다.** “그런데 문제가 있습니다”처럼 짧게 꺾고,
   무엇이 막히는지는 바로 다음 설명에서 구체화한다. 의문만 오래 끌지 않는다.
4. **관점을 바꾸어 해결에 들어간다.** “이에 생각을 바꿉니다” 다음에는 실제
   계산법·구조·작동 과정이 나온다. 대단한 발상이라고 평가하는 문장으로 때우지 않는다.
5. **원리에서 사용 결과까지 간다.** 무엇을 넣고 어떻게 계산해 무엇을 얻는지
   보여준 뒤, 처음 막혔던 문제가 어떻게 풀렸는지로 닫는다.

이는 선호하는 전개 방식이며 모든 주제에 다섯 단계를 억지로 붙이는 규칙은 아니다.
앞의 답이 새 문제를 만드는 관계는 [질문 사슬 기준](../docs/creative-gates.md)을 따른다.
모든 문단을 물음표로 끝내거나, 도입 첫 문장을 질문으로 바꾸지 않아도 된다.
암묵적인 질문도 실제 문장과 문맥을 인용해 검토한다. 게이트를 맞추려고 질문이나
인과관계를 만들어내지 않는다.

## 어투: 설명하다가 짧게 속내를 덧붙인다

| 특징 | 이 도입에서 하는 일 | 다른 대본에 적용할 때 |
| --- | --- | --- |
| 담담한 서술 | “행성이 있습니다”, “돌고 있죠”로 화면을 먼저 이해시킨다. | 큰 감탄사 없이 대상과 동작부터 말한다. |
| 긴 설명 뒤 짧은 덧말 | “근일점으로부터의 각도까지도요.”가 앞 설명의 범위를 한 번 더 짚는다. | 긴 문장을 모두 같은 길이로 자르지 않고, 의미 있는 짧은 덧말을 살린다. |
| 건조한 능청 | “환장할 노릇이죠”로 구체적인 난점에 대한 답답함을 잠깐 내비친다. | 이미 설명한 어려움에 어울릴 때만 쓴다. 사람을 비하하거나 농담을 새로 끼워 넣지 않는다. |
| 말하듯 맺는 문장 | “구하기로 말이죠”가 계산 접근법으로 자연스럽게 이어진다. | 모든 문장을 교과서식 “…입니다”로 평준화하지 않는다. |
| 설명하는 사람과 시청자의 같은 시선 | 아는 것과 막히는 것을 함께 확인하고 다음 방법을 택한다. | 정답을 훈계하기보다, 왜 다음 계산이 필요한지 따라갈 수 있게 말한다. |

주로 `…습니다`, `…죠`로 설명하되 `…까지도요`, `…말이죠` 같은 짧은 맺음을
필요한 곳에 섞는다. 어미를 일정한 순서로 교체하거나 사용 횟수를 맞추지 않는다.
짧은 전환과 조금 길게 흐르는 설명을 함께 둔다. 모든 문장을 같은 길이로 나누거나
접속사와 반응 문장을 하나씩 배치하는 방식으로 리듬을 만들지 않는다.

“환장할 노릇이죠”는 이 원고에서 사용자가 고른 표현이다. 앞으로 모든 영상에
이 문구나 같은 강도의 감정을 넣으라는 지시가 아니다. 말투를 흉내 내기 위해
익숙한 문구를 반복하면 다시 틀에 박힌 대본이 된다.

## 사용자 원고를 다듬을 때

- 원문부터 읽고 문장 길이, 어미, 짧은 덧말, 전환, 농담을 먼저 파악한다.
  사용자가 쓴 원고와 편집본은 구분해 보존한다.
- 이미 말이 되는 문장은 그대로 둔다. 특히 도입의 호흡을 “더 매끈한 설명”으로
  통째로 교체하지 않는다. 사용자가 고른 구체적인 말과 곁말을 우선한다.
- 사실 오류·애매한 지시 대상·빠진 연결처럼 고칠 이유가 있는 부분만 손댄다.
  사실 관계를 고칠 때도 그 주변 어휘와 문장 끝은 가능한 한 유지한다.
- 원문에 없는 비유·예고·교훈을 편집 과정에서 새로 붙이지 않는다. 새 원고를
  작성할 때 비유가 필요하면 실제 이해에 도움이 되는지 먼저 판단한다.
- “사람이 쓴 느낌”을 이유로 역사 속 인물의 생각이나 과학적 사실을 지어내지 않는다.
  능청스러운 반응과 사실 주장은 구분한다.
- “인트로만” 같은 수정 범위를 지킨다. 뒤의 설명까지 같은 문체로 다시 쓰려면
  사용자가 그렇게 요청했는지 먼저 확인한다.

이 대본에서의 최소 수정 예:

> 원문: 측정할 방법이 없어 환장할 노릇이죠.
>
> 편집: 직접 재기도 어려워 환장할 노릇이죠.

거리 측정법이 없다는 사실 주장은 고치되 사용자의 반응은 보존한 것이다.
`단반경`을 해당 공식의 `장반경`으로 바로잡는 일도 같은 원칙이다. 반면 원문에
없던 줄자 비유를 넣고 계산을 예고하는 문장으로 문단 전체를 다시 쓰는 것은,
이번처럼 원문 말투를 살리는 편집의 범위를 벗어난다. 줄자라는 비유 자체를
모든 새 대본에서 금지한다는 뜻은 아니다.

## 검토와 음성 설정의 경계

대본을 웹에 제시하기 전에 다음을 직접 읽어 확인하고, 필요한 근거를
`release-review.md`에 짧게 남긴다.

- 화면의 대상에서 시작해 아는 것과 남은 문제가 자연스럽게 이어지는가?
- 사용자가 고른 문장을 불필요하게 다시 쓰거나, 새 비유·예고로 대체하지 않았는가?
- 짧은 덧말과 전환이 실제 의미를 더하는가? 같은 문구를 습관적으로 반복하지 않는가?
- 용어·수식은 지금 필요한 문제를 푸는 데 쓰이는가? 무엇을 구했는지 결말에서 드러나는가?
- 과학적으로 바꾼 부분과 말투를 위해 바꾼 부분을 구분해 설명할 수 있는가?

이는 에이전트의 편집 검토이며 자동으로 사람의 말투를 판별하는 CLI 게이트가 아니다.
추가 사용자 승인 단계를 만들지 않는다. 기존 대본·프리뷰·초본 승인 절차를 따른다.

이 문서는 나레이션의 **문장과 전개** 기준이다. TTS 화자·톤 프리셋·말하기 속도를
변경하는 설정이 아니다. `voice.emotion_mode=off`이면 이 말투를 이유로 감정·강도
표기를 추가하지 않는다. 실제 음성의 발음과 음색 일관성은 별도 음성 검토에서 확인한다.

`두 번째 준위`, 수치와 단위, 수식어와 핵심 명사처럼 한 묶음으로 전달할
표현 안에는 불필요한 쉼표·`sentence_pauses`를 넣지 않는다. 생성 뒤에는
[쉼 검증](../docs/voice-pause-qa.md)으로 실제 파형을 확인한다. 대본의 문장부호가
정확하다는 이유로 음성의 호흡까지 통과했다고 기록하지 않는다.
